# 큐기출 개선 가이드라인 (A to Z) — 보안 → 통신 → Docker → 배포

> 본 문서는 `_큐기출_팀협업_A_to_Z_가이드_v2.md` 이행 결과 감사에서 발견된 이슈를 모두 해소하고, 운영 단계(Docker / 배포)까지 끌고 가는 **순차 실행 매뉴얼**이다.
> 위에서부터 순서대로 따라가면 된다. 단계마다 "왜 필요한가 → 무엇을 → 어떻게" 형식.
>
> 우선순위
> - **P0 (보안)** — 지금 당장. Git 푸시 전 무조건.
> - **P1 (통신/기능 버그)** — 빌드는 되지만 런타임에 깨지는 9개 지점.
> - **P2 (누락 기능)** — 가이드 명세에 있는데 구현 안 된 것.
> - **P3 (품질/관측성)** — 운영 가기 전 정리.
> - **P4 (Docker)** — 3-tier 컨테이너화.
> - **P5 (배포)** — EC2 / 도메인 / HTTPS / CI/CD.

## P1-1. `/api/auth/me` 경로 정렬

**문제**: 프론트는 `GET /api/auth/me` 호출, 백엔드는 `/api/users/me`에 구현되어 있음.

**수정 — `qgichul-backend/.../controller/AuthController.java`**:
```java
// AuthController에 추가
@GetMapping("/me")
public ResponseEntity<?> me(Principal principal) {
    if (principal == null) return ResponseEntity.status(401).build();
    return ResponseEntity.ok(userService.findByEmail(principal.getName()));
}
```
또는 `UserController`의 매핑을 `/api/auth/me`로 옮기고 컨트롤러 명칭을 정리.

## P1-3. `selectedChoice` ↔ `selectedAnswer` 필드 불일치

**문제**: 프론트는 `selectedAnswer` 보내고, DTO는 `selectedChoice` 필드로 받음 → 항상 null.

**수정 — `dto/request/SubmitAnswerRequest.java`**:
```java
@Getter @Setter
public static class AnswerDto {
    private Long questionId;
    private Integer selectedAnswer;  // 변경: selectedChoice → selectedAnswer
}
```
연쇄 수정: `SessionService.submitAndGrade`, `SessionService.saveTempAnswer`에서 `getSelectedChoice()` → `getSelectedAnswer()`로 일괄 치환.

## P1-4. Submit body 누락

**문제**: 프론트 `submitExam(sessionId)`가 body 없이 POST. 백엔드는 `@RequestBody SubmitAnswerRequest` 요구.

**전략 결정 필요**:
- **(권장) 임시저장 방식 채택**: 답안은 매번 PATCH로 저장됐으므로 submit은 단순 채점 트리거. 백엔드를 body 없이 받게 변경.

**수정 — `SessionController.submitAnswers`**:
```java
@PostMapping("/api/sessions/{sessionId}/submit")
public ResponseEntity<SubmitResultResponse> submitAnswers(@PathVariable Long sessionId) {
    return ResponseEntity.ok(sessionService.gradeBySession(sessionId));
}
```

**수정 — `SessionService`에 메서드 추가**:
```java
@Transactional
public SubmitResultResponse gradeBySession(Long sessionId) {
    ExamSession session = examSessionRepository.findById(sessionId)
        .orElseThrow(() -> new RuntimeException("세션 없음"));
    List<UserAnswer> answers = userAnswerRepository.findByExamSessionId(sessionId);

    int correctCount = (int) answers.stream().filter(a -> Boolean.TRUE.equals(a.getIsCorrect())).count();
    int total = session.getTotalCount() != null ? session.getTotalCount() : answers.size();
    double score = total > 0 ? Math.round(((double) correctCount / total) * 1000) / 10.0 : 0.0;

    session.setCorrectCount(correctCount);
    session.setScore(score);
    session.setStatus("SUBMITTED");
    session.setSubmittedAt(LocalDateTime.now());
    examSessionRepository.save(session);

    return SubmitResultResponse.builder()
        .totalQuestions(total)
        .correctCount(correctCount)
        .wrongCount(total - correctCount)
        .score(score)
        .build();
}
```

`UserAnswerRepository`에 `List<UserAnswer> findByExamSessionId(Long sessionId);` 추가.

## P1-8. `AiService` URL & Payload 정렬

**문제**: 백엔드가 `POST {ai.server.url}/analyze`를 호출하지만 AI 서버 라우터는 `POST /api/ai/analysis`. 또한 payload 키가 `email/stats` vs `user_id/wrong_answers`로 어긋남.

**수정 — `AiService.getAnalysisFromAi`**:
```java
String endpoint = aiServerUrl + "/api/ai/analysis";

Map<String, Object> requestPayload = new HashMap<>();
requestPayload.put("user_id", email);
requestPayload.put("wrong_answers", userStats.stream()
    .map(s -> Map.of("subject", s.getSubject(), "rate", s.getRate()))
    .toList());

return restTemplate.postForObject(endpoint, requestPayload, AiAnalysisResponse.class);
```

AI 서버 `routers/analysis.py`의 `WrongAnswerItem` 스키마와 정확히 맞춰야 함. (스키마 쪽이 더 풍부한 데이터를 요구하면 백엔드에서 그 형태로 채워서 보낸다.)

`qgichul-frontend/nginx.conf`:
```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    # SPA fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 백엔드 프록시 (선택)
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    gzip on;
    gzip_types text/plain text/css application/json application/javascript;
}
```

## P5-6. 도메인 + HTTPS (nginx + Certbot)

> 도메인이 있을 때만. 가비아·Route53 등에서 EC2 IP를 A 레코드로.

호스트(EC2)에 nginx + certbot 설치하고, 컨테이너 프론트엔드는 80 대신 8081로 매핑:

```yaml
# docker-compose.yml
  frontend:
    ports:
      - "8081:80"
```

호스트 nginx (`/etc/nginx/sites-available/qgichul`):
```nginx
server {
    listen 80;
    server_name qgichul.com www.qgichul.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name qgichul.com www.qgichul.com;

    ssl_certificate /etc/letsencrypt/live/qgichul.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/qgichul.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Certbot:
```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo ln -s /etc/nginx/sites-available/qgichul /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d qgichul.com -d www.qgichul.com
sudo systemctl enable certbot.timer
```

# 부록 C. 자주 만나는 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| `OPENAI_API_KEY environment variable is not set` | `load_dotenv()` 누락 또는 `.env` 미배치 | main.py 상단에 추가, `.env`를 컨테이너 작업 디렉토리에 마운트 또는 compose env로 주입 |
| 프론트에서 401만 무한 반복 | 토큰 만료 후 응답 인터셉터가 `/login` 리다이렉트 → 로그인 → 다시 같은 토큰? | 로그인 후 `localStorage.setItem('accessToken', ...)` 빠졌는지 확인 |
| `CORS error` | 백엔드 SecurityConfig CORS origin 누락 | `setAllowedOrigins`에 프론트 도메인 추가 |
| `Communications link failure` (DB) | TiDB 보안그룹 / SSL 옵션 / IP 화이트리스트 | TiDB Cloud → Network → IP Access List에 EC2 IP 추가 |
| Docker 빌드 OOM (t3.small) | gradle 빌드 메모리 부족 | 로컬에서 `docker build` → `docker push` to ECR/Docker Hub → EC2에서는 pull만 |
| nginx 502 Bad Gateway | 프론트엔드 컨테이너 미기동 또는 포트 매핑 오류 | `docker compose ps`, `docker compose logs frontend` |
| `selectedAnswer null` 채점 항상 오답 | P1-3 미적용 | DTO 필드명 일치 확인 |

---

이 문서대로 위에서 아래로 진행하면 보안 → 기능 정확성 → 컨테이너화 → 운영까지 한 번에 정리된다. 각 P 단위가 끝날 때마다 커밋 메시지에 단계 명시 (예: `chore(P0): rotate secrets and add gitignore`).
